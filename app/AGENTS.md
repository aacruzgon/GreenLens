The PDM app: Expo SDK 57, React Native 0.86, Expo Router, `@clerk/expo` 4.x, TypeScript strict. Built for the iPhone; the web build comes last.

Expo changes every SDK: check the v57 docs (`https://docs.expo.dev/versions/v57.0.0/`) instead of memory.

## Commands

```sh
npx expo install <pkg>      # never a plain npm install for Expo or native packages
npm start                   # Expo Go; press i for the iOS simulator
npm run gen:api             # regenerate src/api/generated/schema.ts after a backend contract change
npm run typecheck && npm run lint && npm test && npm run check:contrast
npx expo run:ios --device   # a development build: the LiDAR module, GardenView and the Live Activity (roadmap F5)
```

Native code lives in `modules/` (local Expo modules: `lidar`, `live-activity`) and `targets/` (the widget extension, added by `@bacons/apple-targets`). `ios/` is generated by `npx expo prebuild` and never committed; prebuild rewrites `package.json`'s `ios` script, so put that line back afterwards. Features reach the modules only through `src/platform`, which an ESLint zone enforces.

`.env` comes from `.env.example`. `EXPO_PUBLIC_API_MODE=mock` with an empty Clerk key runs with no backend and a demo sign-in. `EXPO_PUBLIC_DEV_TOOLS=1` makes a development or evaluation build: the LiDAR tools in Settings and Documents in the Files app. Leave it empty for a build that goes to users, and prebuild again after changing it.
